# Готовые файлы к практике 8

Ограничение ресурсов контейнера. Два файла: нагрузка на память
и пример ограничений для Compose.

| Файл | Что это |
|---|---|
| `stress/mem-hog.py` | Просит память блоками, пока контейнер не убьёт предел `--memory` |
| `compose-limits.yml` | Ограничения в Compose: `deploy.resources.limits` |

## stress/mem-hog.py

Просит память блоками по 16 МБ (размер блока — первый аргумент)
и записывает по одному байту в начало каждой страницы. Запись
обязательна: память, которую процесс запросил, но не тронул, ядро
не выделяет, и опыт превратился бы в демонстрацию отсутствия
ограничения.

Скрипт печатает, сколько уже занято. Вывод обрывается на строке,
после которой контейнер убит лимитом: код возврата 137 и
`OOMKilled: true` в `docker inspect`.

## compose-limits.yml

Один сервис с ограничениями в разделе `deploy.resources`: жёсткие
пределы по памяти, процессору и числу процессов. Тот же синтаксис
работает в стеке Swarm (практика 7); короткие ключи `mem_limit`
и `cpus` — только в Compose и только для одного контейнера.

Проверка:

```bash
docker compose -f compose-limits.yml up -d
docker inspect p8-resources-web-1 \
    --format '{{.HostConfig.Memory}} {{.HostConfig.NanoCpus}}'
docker compose -f compose-limits.yml down
```

Каталог `stress` монтируется в контейнер только для чтения:
`./stress` → `/stress`.
