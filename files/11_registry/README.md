# Файлы к практике 11

Свой реестр образов на машине `admin`: `registry:3` с TLS, входом
по паролю и томом для данных.

| Файл | Что это |
|---|---|
| `docker-compose.yml` | Реестр `registry:3`: порт, три монтирования, том данных, healthcheck |
| `registry/config.yml` | Настройка самого реестра: хранилище, удаление тегов, TLS, htpasswd |

Больше в каталоге ничего нет намеренно. Сертификаты (`certs/`), файл
паролей (`auth/htpasswd`) и том с данными создаются командами из текста
практики и в курс не попадают.

## `docker-compose.yml`

Порт публикуется на адрес машины `admin` (`${REGISTRY_BIND:-10.0.2.5}`),
настройка, сертификаты и файл паролей монтируются внутрь только для
чтения, данные реестра лежат в именованном томе `registry-data`.

## `registry/config.yml`

Файл читает сам реестр, а не Docker. Внутри контейнера он должен лежать
по пути `/etc/distribution/config.yml`: в `registry:2` и в старых
инструкциях это было `/etc/docker/registry/config.yml`. Файл по старому
пути реестр не заметит и запустится по HTTP и без пароля.

Первая строка файла, `version: 0.1`, обязательна: `registry:3` без неё
не стартует. К устаревшему полю `version` в файлах Compose она отношения
не имеет: `tools/validate_files.py` ищет это поле только в файлах Compose,
у которых есть раздел `services`.

## До запуска

В каталоге должны появиться `certs/registry.crt`, `certs/registry.key`
и `auth/htpasswd`. Как их получить — в тексте практики 11.
