# Готовые файлы к практике 4

Файлов здесь два, и оба нужны для опыта с MySQL: один задаёт значения
окружения, второй — начальную схему базы.

| Файл | Что это |
|---|---|
| `.env.example` | Образец значений окружения для MySQL. Копируется в `.env` |
| `mysql/init/01_schema.sql` | Схема базы: выполняется при пустом томе |

## `.env.example`

Образца достаточно, чтобы запустить MySQL: значения в нём — заготовки
(`change_me_before_use`), а не пароли. Рабочий `.env` студент создаёт
сам командой `cp .env.example .env`.

Настоящего `.env` в курсе нет и быть не должно: этот файл уезжает
в git вместе с историей, а пароль, попавший в репозиторий, остаётся
там навсегда — даже если файл потом удалить.

## `mysql/init/01_schema.sql`

Файлы из `/docker-entrypoint-initdb.d` образ выполняет только при
первой инициализации, то есть когда каталог данных пуст. Отсюда два
вывода, которые проверяются в практике: на существующем томе этот файл
не выполняется второй раз, и правка в нём ничего не изменит.

Текст записи в файле латиницей намеренно: клиент `mysql` считает ширину
колонки по числу байт, а кириллическая буква занимает два байта — строки
в таблице разъезжаются.

## Про версии образов

В практике используются `mysql:8.4` (действующий LTS-выпуск) и
`alpine:3.24` для контейнера с `tar`. Тег `latest` в курсе не
используется: он означает «то, что было в реестре в момент скачивания»,
и занятие через месяц покажет другой результат.
