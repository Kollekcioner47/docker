# Готовые файлы к практике 3

Здесь пять каталогов — пять ступеней одной сборки. Начинается она
с трёх строк, а заканчивается многоэтапным Dockerfile: ровно так, как
идут шаги практики. Скриптов нет: все команды студент набирает сам,
а готовые файлы нужны, только если что-то не набралось.

## Что здесь лежит

| Каталог | Что это |
|---|---|
| `01_hello/` | Шаг 1: самый короткий Dockerfile из трёх строк — печатает приветствие |
| `02_workdir/` | Шаг 2: тот же файл плюс `WORKDIR /app` — код ложится в свой каталог |
| `03_web/` | Шаг 3: приложение на Flask, зависимости и порт 8000 |
| `04_user/` | Шаг 4: добавлены `.dockerignore` и работа не от root |
| `05_multistage/` | Шаг 5: две стадии сборки, зависимости ставятся в `builder` |

## Про каждый каталог коротко

**`01_hello/`.** `app.py` печатает одну строку, `Dockerfile` состоит
из `FROM`, `COPY` и `CMD`. Образ весит 118 МБ — это базовый
`python:3.13-slim`, сам файл добавляет к нему меньше сотни байт.

**`02_workdir/`.** `app.py` не изменился, в `Dockerfile` появилась
строка `WORKDIR /app`. Она задаёт рабочий каталог и для инструкций
ниже, и для запуска контейнера, поэтому `COPY app.py .` кладёт файл
в `/app`. Каталог создаётся сам.

**`03_web/`.** Настоящее приложение: `/` отдаёт приветствие, `/health` —
состояние. В `requirements.txt` одна строка, `flask`, — без версии,
чтобы в шаге 8 было о чём поговорить. `requirements.txt` копируется
до кода: тогда правка `app.py` не сбрасывает слой с установкой
зависимостей (разбор — шаг 6). Образ весит 131 МБ.

**`04_user/`.** Тот же образ, но процесс идёт от пользователя `app`
с uid 1000, а рядом лежит `.dockerignore` со списком того, что
не должно попадать в контекст сборки. Размер не меняется: пользователь
занимает девять килобайт.

**`05_multistage/`.** Первая стадия (`builder`) ставит зависимости
в отдельный каталог `/install`, вторая забирает его одной инструкцией
`COPY --from=builder`. Всё, что осталось в первой стадии, в готовый
образ не переходит. Выигрыш здесь небольшой — 123 МБ против 131, —
и в шаге 5 сказано, почему так и где многоэтапная сборка решает.

## Порядок применения

Каждый каталог собирается отдельно, изнутри себя:

```bash
cd files/03_dockerfile/01_hello
docker build -t hello:1 .
docker run --rm hello:1

cd ../03_web
docker build -t hello:3 .
docker run -d --name p3-web -p 8000:8000 hello:3
curl -s http://127.0.0.1:8000/health
docker rm -f p3-web
```

Проверено на Docker Engine 28.5.1 (BuildKit): собираются и запускаются
все пять вариантов, размеры образов — 118, 118, 131, 131 и 123 МБ,
`docker run --rm hello:4 id` отвечает `uid=1000(app)`, а `/health`
возвращает `{"status":"ok"}`.
