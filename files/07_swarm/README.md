# Готовые файлы к практике 7 — Docker Swarm

Это каталог единственной практики курса, которая идёт на трёх машинах:
`admin` становится менеджером кластера, `node1` и `node2` — рабочими
узлами.

| Файл | Что это |
|---|---|
| `docker-stack.yml` | Описание стека «Заметки»: MySQL, backend, frontend |
| `backend/app.py` | Приложение: читает пароль из файла секрета, отдаёт `/healthz` |
| `backend/requirements.txt` | Зависимости с закреплёнными версиями: Flask и PyMySQL |
| `backend/Dockerfile` | Сборка backend-образа от непривилегированного пользователя |
| `frontend/default.conf` | Конфигурация nginx: слушает 8080, проксирует на `backend:5000` |
| `frontend/Dockerfile` | Сборка frontend-образа: `USER nginx`, healthcheck на `/healthz` |
| `mysql-init/init.sql` | Схема базы: таблица заметок |
| `README.md` | Этот файл |

Подготовка узлов (порты, `/etc/hosts`, время) и все команды работы
с кластером — в тексте практики `7_swarm.txt`: студент набирает их сам,
готовых скриптов в каталоге нет.

## Файл стека

`docker-stack.yml` записан тем же синтаксисом, что файл Compose,
но раздел `deploy` в нём рабочий: `replicas`, `placement`,
`restart_policy`, `update_config`, `resources`.

Паролей в файле нет — только имена секретов: значения создаются
на менеджере командой `docker secret create` и в файл не попадают.
База закреплена за узлом с меткой `role=db`: локальный том на другую
машину не переезжает. Схема базы передаётся как `config`, а не привязкой
каталога: узел, на котором запустится задача, про каталог курса
ничего не знает.

Чего в разделе `deploy` быть не может: ключей `build`, `depends_on`,
`restart` и `container_name`. Swarm их игнорирует и печатает
`Ignoring unsupported options`. Готовность сервисов проверяется
`healthcheck`, а подключение к базе приложение повторяет само.

## Почему в конфигурации nginx есть resolver

Имя сервиса из `proxy_pass` nginx разбирает один раз — при запуске.
Если сервиса `backend` в этот момент в DNS ещё нет, nginx не стартует
вовсе, и задача перезапускается по кругу. Поэтому адрес вынесен
в переменную, а разбор имени поручен встроенному DNS Docker:

```nginx
resolver 127.0.0.11 valid=10s;
set $backend_upstream http://backend:5000;
```

Плата за это — опечатка в имени сервиса видна не при запуске,
а ответом 502.

## Образы

Swarm не собирает образы и не передаёт их узлам. Образы собирают
на `admin` из этого каталога и раздают узлам — команды `docker build`,
`docker save`, `docker load` приведены в шаге 5 практики. В рабочей
среде вместо переноса файлом используют реестр (практика 11).
