# Практика 2. Образы и контейнеры

Готовых файлов в этом каталоге нет, и это намеренно. В практике 2 нет
ни одного действия, которое нельзя выполнить командой в терминале,
а текст практики — [`2_basics.txt`](../../2_basics.txt) в корне курса.
Скриптов-обёрток в курсе нет: команду, которую набрал сам, помнишь,
а запущенный чужой скрипт — нет.

Здесь лежит только эта памятка: команды практики в одну строку каждая.

## Команды

| Команда | Что делает |
|---|---|
| `docker pull alpine:3.24` | скачивает образ с закреплённым тегом |
| `docker images` | список скачанных образов |
| `docker run -d --name p2-sleeper alpine:3.24 sleep 300` | создаёт контейнер и запускает его в фоне |
| `docker run --rm -it alpine:3.24 sh` | запускает контейнер и заходит внутрь |
| `docker ps` | запущенные контейнеры |
| `docker ps -a` | все контейнеры, включая остановленные |
| `docker stop` / `docker start` / `docker restart` | остановить, запустить снова, перезапустить |
| `docker rm` / `docker rm -f` | удалить остановленный / работающий контейнер |
| `docker logs --tail 3 p2-logs` | последние строки журнала контейнера |
| `docker logs -f p2-logs` | следить за журналом (выход — Ctrl+C) |
| `docker exec -it p2-sleeper sh` | запустить ещё один процесс внутри контейнера |
| `docker inspect --format '{{.State.ExitCode}}' p2-ok` | взять одно поле из описания контейнера |
| `docker update --restart unless-stopped p2-r-al` | сменить политику перезапуска |
| `docker system df` | сколько места занимает Docker |
| `docker system prune` | удалить неиспользуемое; опасно, разбор — в практике |

## Коды возврата

| Код | Что значит |
|---|---|
| 0 | процесс завершился успешно |
| 1 | ошибку вернуло приложение, смотреть журнал |
| 127 | команды нет внутри образа; контейнер остаётся в состоянии `created` |
| 137 | процесс убит сигналом SIGKILL: кончилась память или истёк таймаут `docker stop` |
| 143 | процесс получил SIGTERM и обработал его (аккуратное завершение) |

## Имена контейнеров практики

Контейнеры практики названы с префиксом `p2-`. По нему их видно,
и убирать их удобно по имени:

```bash
docker ps -a --filter name=p2-
docker rm -f p2-sleeper p2-keep p2-logs
```

Метка (label) `docker-course.practice=2` пригодится дальше, там, где
одним занятием создаётся много контейнеров: в практике 8 по метке
видно, чьи контейнеры на машине, а в практике 12 метка — готовый пример
того, как в аудите ищут «кто и что запускал»:

```bash
docker container prune --filter label=docker-course.practice=2
```

Уборка в курсе всегда называется по имени или по метке. Команды без
фильтра — `docker system prune`, `docker image prune -a` — действуют
на всю машину и удаляют в том числе чужие образы.
