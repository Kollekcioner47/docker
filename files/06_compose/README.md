# Готовые файлы к практике 6: Docker Compose

Здесь лежит приложение «Заметки» целиком: веб-часть на Flask и база
PostgreSQL. Каталог можно скопировать на машину и запустить одной
командой — так, как это описано в практике.

| Файл | Что это |
|---|---|
| `notes/docker-compose.yml` | описание двух сервисов: `web` и `db` |
| `notes/.env.example` | образец значений: имена базы, пароль, порт |
| `notes/app/app.py` | приложение на Flask: заметки в базе |
| `notes/app/requirements.txt` | зависимости: Flask и psycopg |
| `notes/app/Dockerfile` | образ приложения |

Поля `version:` в файле Compose нет: в Compose v2 оно устарело
и вызывает предупреждение «the attribute `version` is obsolete».
Секретов открытым текстом в файлах нет: значения приходят из `.env`,
который создаётся копированием из `.env.example` и в репозиторий
не попадает.

## Порядок работы

```bash
cd notes
cp .env.example .env
docker compose config          # проверка подстановки переменных
docker compose up -d --build
curl -s http://localhost:8080/healthz
```

## Что важно в этом приложении

**Два сервиса — две роли.** `web` собирается из `app/` и публикует порт
на машину; `db` берёт готовый образ `postgres:18-alpine` и хранит
данные в томе. Обращаться к базе из кода можно по имени сервиса: `db`.

**Порт.** Публикуется `${NOTES_PORT:-8080}:5000`: снаружи 8080, внутри
приложения всегда 5000. Если 8080 занят другим контейнером, меняется
значение в `.env`, а не файл Compose.

**Данные.** Том `pgdata` подключён к `/var/lib/postgresql` — в образе
`postgres:18` каталог данных равен `/var/lib/postgresql/18/docker`,
и том объявлен на уровень выше. При `docker compose down` том остаётся,
при `down -v` удаляется вместе с данными.

**Почему `depends_on` с условием.** У базы есть healthcheck
(`pg_isready`), а `web` ждёт `condition: service_healthy`. Без условия
`depends_on` ждёт только запуска контейнера, и приложение отвечает 500,
пока база инициализирует каталог данных.

## Уборка

```bash
docker compose down        # убрать контейнеры и сеть, данные сохранить
docker compose down -v     # ещё и том, вместе с данными базы
```

## Что делать, если что-то не работает

Практика 6 содержит раздел «Если что-то пошло не так»: не установлен
плагин `compose`, ошибки разбора YAML, незаданная обязательная
переменная, занятый порт и другие типовые случаи.
