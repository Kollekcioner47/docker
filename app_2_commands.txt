Приложение 2. Шпаргалка: команды курса по практикам.

ЭТО ПРИЛОЖЕНИЕ — СВОДКА, А НЕ УЧЕБНИК. Здесь собраны команды, которые
в курсе действительно выполнялись, с пояснением в одну строку. Держите
шпаргалку открытой рядом с практикой: она напоминает синтаксис, когда
вы уже понимаете, что делаете.

  Команды записаны без символа $, как и во всём курсе. Угловые скобки —
  то, что заменяют своим значением. Имена контейнеров начинаются
  с номера практики (p5-nginx). Это не список всех ключей: полный
  набор показывает команда docker <команда> --help.

#########################################################################
ЧАСТЬ 1. БАЗОВЫЙ DOCKER: ПРАКТИКИ 1-6
#########################################################################

=========================================================================
ПРАКТИКА 1. СТЕНД И УСТАНОВКА DOCKER
=========================================================================

  sudo systemctl enable --now docker
    включить службу демона и запустить её сразу
  docker version
    версии клиента и сервера: если сервер отвечает, Docker работает
  docker run --rm hello-world
    проверка, что демон, сеть и реестр работают
  id -nG
    список групп пользователя: нужна группа docker

=========================================================================
ПРАКТИКА 2. ОБРАЗЫ И КОНТЕЙНЕРЫ
=========================================================================

  docker pull alpine:3.24
    скачать образ; тег закреплён, latest не используется
  docker run -d --name p2-web nginx:1.30-alpine
    запустить контейнер в фоне и дать ему имя
  docker ps -a
    все контейнеры, включая остановленные
  docker logs --tail 20 p2-web
    последние строки журнала; с -f — следить в реальном времени
  docker exec -it p2-web sh
    второй процесс внутри работающего контейнера
  docker stop p2-web
    вежливая остановка: SIGTERM, затем SIGKILL по таймауту
  docker rm p2-web
    удалить остановленный контейнер; -f удаляет вместе с остановкой
  docker inspect p2-web --format '{{.State.ExitCode}}'
    код возврата: 0 — успех, 1 — ошибка, 137 — SIGKILL, 143 — SIGTERM

=========================================================================
ПРАКТИКА 3. DOCKERFILE: СЛОИ, КЭШ, МНОГОЭТАПНАЯ СБОРКА
=========================================================================

  docker build -t app:1 .
    собрать образ из Dockerfile в текущем каталоге
  docker build --progress=plain -t app:1 .
    тот же вывод без анимации: видно каждый шаг и попадание в кэш
  docker build --no-cache -t app:1 .
    отключить кэш — когда нужно проверить сборку с нуля
  docker build -f Dockerfile.multistage -t app:1 .
    взять другой файл сборки: так сравнивают размеры образов
  docker image history app:1
    слои образа и их вес: сразу видно, где раздувается размер

=========================================================================
ПРАКТИКА 4. ДАННЫЕ: ТОМА И МОНТИРОВАНИЕ
=========================================================================

  docker volume create dbdata
    создать именованный том; docker volume ls перечисляет тома
  docker run -d --name p4-db -v dbdata:/var/lib/mysql mysql:8.4
    подключить том к контейнеру: данные переживут его удаление
  docker run -d --name p4-web \
      -v "$PWD/html:/usr/share/nginx/html:ro" nginx:1.30-alpine
    привязать каталог хоста; :ro запрещает запись из контейнера
  docker run --rm -u "$(id -u):$(id -g)" -v "${PWD}:/data" \
      alpine:3.24 sh -c 'touch /data/file'
    запуск от имени своего пользователя: файлы не станут принадлежать root
  docker volume rm dbdata
    удалить том; занятый том удалить нельзя — сначала контейнер

=========================================================================
ПРАКТИКА 5. ПОРТЫ И СЕТИ DOCKER
=========================================================================

  docker run -d --name p5-web -p 127.0.0.1:8080:80 nginx:1.30-alpine
    опубликовать порт 80 контейнера на порт 8080 хоста
  docker network ls
    список сетей: bridge, host, none и созданные вручную
  docker network create p5-net
    своя сеть: в ней работает разрешение имён по имени контейнера
  docker run -d --name p5-nginx --network p5-net nginx:1.30-alpine
    запуск контейнера в своей сети
  docker exec p5-client ping -c 1 p5-nginx
    проверка по имени: в своей сети отвечает, в сети по умолчанию — нет
  docker network inspect p5-net --format '{{json .Containers}}'
    кто подключён к сети, в машиночитаемом виде

=========================================================================
ПРАКТИКА 6. DOCKER COMPOSE
=========================================================================

  docker compose config
    разобрать файл, подставить переменные и показать итог
  docker compose up -d
    создать и запустить все сервисы в фоне
  docker compose ps
    состояние контейнеров проекта
  docker compose logs -f web
    журналы сервиса; без имени — всех сервисов
  docker compose down -v
    остановить и удалить контейнеры, сети и тома проекта: данные
    проекта будут потеряны; без -v тома остаются на месте

#########################################################################
ЧАСТЬ 2. ЭКСПЛУАТАЦИЯ: ПРАКТИКИ 7-12
#########################################################################

=========================================================================
ПРАКТИКА 7. DOCKER SWARM
=========================================================================

  docker swarm init --advertise-addr 10.0.2.5
    сделать машину admin менеджером кластера
  docker swarm join-token worker
    команда для подключения рабочего узла кластера
  docker node ls
    узлы кластера, их роли и состояние
  docker service create --name web --replicas 3 \
      --publish published=8080,target=80 nginx:1.30-alpine
    создать сервис из трёх реплик
  docker service ls
    сервисы кластера и число работающих реплик
  docker service ps web
    задачи сервиса и история перезапусков — журнал сбоев
  docker service scale web=5
    изменить число реплик
  docker stack deploy -c docker-stack.yml notes
    развернуть стек: синтаксис Compose, но раздел deploy работает целиком
  docker secret create db_password ./db_password.txt
    создать секрет из файла: значение в командной строке не остаётся

=========================================================================
ПРАКТИКА 8. ОГРАНИЧЕНИЕ РЕСУРСОВ КОНТЕЙНЕРА
=========================================================================

  docker run -d --name p8-mem --memory 128m python:3.13-slim sleep 300
    жёсткий предел памяти: при превышении ядро убьёт контейнер
  docker inspect p8-mem --format '{{.State.OOMKilled}}'
    был ли контейнер убит ядром из-за памяти
  docker run -d --name p8-cpu --cpus 0.5 alpine:3.24 sleep 300
    половина ядра: понятный и предсказуемый способ
  docker run --rm --pids-limit 20 alpine:3.24 sh -c 'sleep 30'
    предел числа процессов: защита от бомбы форков
  docker stats --no-stream
    один снимок потребления по всем контейнерам

=========================================================================
ПРАКТИКА 9. СЕКРЕТЫ
=========================================================================

  docker inspect p9-app --format '{{json .Config.Env}}'
    переменные окружения видны целиком — секрет в них хранить нельзя
  docker history --no-trunc app:1
    покажет ARG и ENV, попавшие в образ
  docker run -d --name p9-db --env-file .env postgres:18-alpine
    значения из файла, а не из командной строки
  docker run -d --name p9-db2 \
      -e POSTGRES_PASSWORD_FILE=/run/secrets/db_password \
      postgres:18-alpine
    образ читает пароль из файла: в docker inspect виден только путь
  docker build --secret id=token,src=./token.txt -t app:1 .
    передать секрет в момент сборки: в слое он не остаётся

=========================================================================
ПРАКТИКА 10. БЕЗОПАСНОСТЬ ОБРАЗОВ И СКАНИРОВАНИЕ
=========================================================================

  docker run --rm app:1 id
    от какого пользователя работает приложение
  docker image inspect app:1 --format '{{.Config.User}}'
    кем записан USER в образе: пусто — значит root
  docker run --rm --user 1000:1000 app:1 id
    запустить приложение не от root, не пересобирая образ
  docker run --rm -v "${PWD}:/w" aquasec/trivy:0.71.2 \
      image --input /w/app.tar --severity HIGH,CRITICAL
    скан на уязвимости уровня high и critical
  docker pull alpine@sha256:<дайджест>
    забрать образ по неизменяемой ссылке: тег можно переподменить

=========================================================================
ПРАКТИКА 11. СВОЙ РЕЕСТР ОБРАЗОВ
=========================================================================

  docker compose up -d
    поднять реестр registry:3 вместе с TLS-прокси
  docker tag app:1 registry.lab.local:5000/app:1
    имя образа содержит адрес реестра — иначе образ уйдёт в Docker Hub
  docker push registry.lab.local:5000/app:1
    отправить образ в свой реестр
  docker pull registry.lab.local:5000/app:1
    забрать образ из своего реестра
  docker login registry.lab.local:5000 -u engineer --password-stdin
    вход в реестр; пароль передаётся потоком, а не аргументом
  docker exec registry \
      registry garbage-collect /etc/docker/registry/config.yml
    сборка мусора: без неё удалённые слои продолжают занимать место

=========================================================================
ПРАКТИКА 12. БЕЗОПАСНОСТЬ ХОСТА И АУДИТ
=========================================================================

  docker run --rm --cap-drop ALL --cap-add NET_BIND_SERVICE \
      nginx:1.30-alpine
    убрать все возможности и вернуть только нужную
  docker run --rm --security-opt no-new-privileges alpine:3.24 id
    запрет на повышение привилегий внутри контейнера
  docker run --rm --read-only --tmpfs /tmp alpine:3.24 sh -c 'ls /tmp'
    корневая файловая система только для чтения, запись — в tmpfs
  docker events --since 1h
    события демона за последний час
  docker inspect p12-app --format '{{.Created}} {{.Image}}'
    когда создан контейнер и из какого образа
  sudo ausearch -k docker_config -i
    кто и когда менял настройки Docker (нужны правила auditd)

=========================================================================
ЧЕГО В ШПАРГАЛКЕ НЕТ
=========================================================================

  * docker system prune -a БЕЗ ФИЛЬТРА: удаляет все образы, которыми
    не пользуется ни один контейнер;
  * docker volume prune НА МАШИНЕ С ДАННЫМИ: тома не имеют резервных
    копий, удалили — данных нет;
  * КОМАНДЫ «ОСТАНОВИТЬ ВСЁ»: они останавливают и чужие контейнеры,
    а на общей машине это чужая работа;
  * КОМАНДЫ С ОСЛАБЛЕННОЙ ЗАЩИТОЙ: разобраны в практиках 9, 10 и 12.
