Практика 1. Установка Docker.

ЭТА ПРАКТИКА — ПЕРВАЯ. Здесь мы поставим Docker на три машины
и запустим первый контейнер. Всё остальное в курсе выполняется
на этих машинах.


=========================================================================
ЧТО МЫ СДЕЛАЕМ
=========================================================================

Мы соберём лабораторию из трёх машин:

  admin   10.0.2.5   — основная машина, на ней идёт весь курс;
  node1   10.0.2.13  — понадобится в практике 7, для кластера;
  node2   10.0.2.14  — понадобится там же.

Одиннадцать практик из двенадцати выполняются на машине admin.
Узлы node1 и node2 нужны только для одного занятия — но настроить
их нужно сейчас, пока вы помните, что делали.

ЗАЧЕМ СТАВИТЬ DOCKER САМИМ

Потому что в лаборатории видно, из чего состоит Docker: служба,
каталог с образами, сокет. Когда что-то не работает, есть куда
посмотреть. Это и есть разница между «умею запускать контейнеры»
и «понимаю, что происходит».

И ещё: лабораторию можно ломать. Половина пользы курса — в разборе
поломок, а ломать рабочий сервер нельзя. Если эксперимент зашёл
в тупик, есть снимок виртуальных машин.


=========================================================================
ЧТО ПОНАДОБИТСЯ
=========================================================================

ТРИ ВИРТУАЛЬНЫЕ МАШИНЫ с Ubuntu 26.04 LTS:

  admin   10.0.2.5   — 2 ядра, 4 ГБ памяти, диск от 20 ГБ
  node1   10.0.2.13  — 2 ядра, 4 ГБ памяти, диск от 20 ГБ
  node2   10.0.2.14  — 2 ядра, 4 ГБ памяти, диск от 20 ГБ

Памяти больше — не хуже: на машине admin будут ещё база данных,
реестр образов и сборка. Но и четырёх гигабайт хватит, чтобы пройти
весь курс.

ЧТО ЕЩЁ НУЖНО:

  * машины видят друг друга и находятся в одной подсети;
  * есть доступ в интернет: нужно скачать пакеты и образы;
  * учётная запись engineer с правами sudo. Пароль в примерах —
    Console47. В рабочей среде так нельзя, у нас стенд изолирован.

Если у вас другая подсеть — замените адреса на свои. Ошибка в адресах
проявится не сразу, а в практике 7, и будет выглядеть как «узел
недоступен», хотя машина работает.

УСТАНОВКА НА WINDOWS И macOS. Там Docker ставится как Docker Desktop —
отдельная программа, которая прячет Docker внутри виртуальной машины.
Курс рассчитан на Linux, но практики 2–6 и 8–12 на Desktop тоже
проходятся. Разница только в одном: часть команд, которые смотрят
внутрь системы (права на сокет, аудит), на Desktop смысла не имеет.


=========================================================================
ШАГ 1. ГОТОВИМ МАШИНЫ
=========================================================================

Команды этого шага выполняются на КАЖДОЙ из трёх машин.
Подключитесь к каждой под пользователем engineer.

1.1. Обновляем систему и ставим утилиты, которые понадобятся дальше:

  sudo apt update
  sudo apt install -y curl wget vim jq

  ЗАЧЕМ jq: он красиво разбирает вывод docker inspect, а это половина
  отладки в курсе.

1.2. Задаём имена машин. По именам удобнее, чем по адресам:

  sudo hostnamectl set-hostname admin
  # на других машинах — node1 и node2

1.3. Прописываем машины друг другу. Файл /etc/hosts на ВСЕХ трёх
машинах должен быть одинаковым:

  sudo tee -a /etc/hosts > /dev/null <<'EOF'

  # Лаборатория Docker
  10.0.2.5   admin
  10.0.2.13  node1
  10.0.2.14  node2
  EOF

Проверка с любой машины:

  ping -c 1 node1

Если не пингуется — сверьте адрес с настоящим:

  ip -4 addr show

ПОЧЕМУ ЭТО ВАЖНО ПРОВЕРИТЬ СЕЙЧАС: если адрес в /etc/hosts не совпадёт
с настоящим, ошибка проявится только в практике 7, при сборке кластера,
и вы уже забудете, что правили настройки сети.

1.4. Синхронизация времени:

  sudo timedatectl set-timezone Europe/Moscow
  timedatectl status

В выводе должна быть строка «System clock synchronized: yes».
Расхождение часов ломает журналы: в одном журнале одно время,
в другом другое, и понять, что за чем следовало, невозможно.

1.5. Ключ с машины admin на узлы, чтобы не вводить пароль каждый раз:

  # на машине admin
  ssh-keygen -t ed25519 -C "engineer@admin"
  ssh-copy-id engineer@node1
  ssh-copy-id engineer@node2

Проверка — пароль спрашивать не должен:

  ssh node1 hostname


=========================================================================
ШАГ 2. УСТАНОВКА DOCKER
=========================================================================

Тоже на всех трёх машинах.

ПОЧЕМУ НЕ ИЗ apt НАПРЯМУЮ: в репозиториях Ubuntu есть пакет docker.io,
и это не тот Docker. Его собирает Canonical, он отстаёт от проекта
на месяцы и не содержит плагина Compose, который нужен в практике 6.
Ставим из официального репозитория Docker.

2.1. Пакеты, нужные apt для работы по HTTPS:

  sudo apt update
  sudo apt install -y ca-certificates curl gnupg

2.2. Ключ подписи репозитория Docker:

  sudo install -m 0755 -d /etc/apt/keyrings
  sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
      -o /etc/apt/keyrings/docker.asc
  sudo chmod a+r /etc/apt/keyrings/docker.asc

  ЗАЧЕМ КЛЮЧ: apt отказывается ставить пакеты из репозитория, который
  не может проверить. Ключ — это подпись проекта Docker.

  ИСПРАВЛЕНО: в прежней версии курса ключ сохраняли
  в /usr/share/keyrings/docker-archive-keyring.gpg. Сейчас документация
  Docker указывает /etc/apt/keyrings/docker.asc, потому что каталог
  /usr/share/keyrings делят между собой другие пакеты. Со старым путём
  apt update ругается на «NO_PUBKEY».

2.3. Подключаем репозиторий:

  echo "deb [arch=$(dpkg --print-architecture) \
  signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo $VERSION_CODENAME) stable" | \
      sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

  sudo apt update

Кодовое имя выпуска берётся из самой системы: на Ubuntu 26.04 это
resolute, на 24.04 — noble. Так команда не устареет при переходе
на следующий выпуск.

2.4. Устанавливаем:

  sudo apt install -y \
      docker-ce \
      docker-ce-cli \
      containerd.io \
      docker-buildx-plugin \
      docker-compose-plugin

  docker-ce               — сам Docker, он же демон;
  docker-ce-cli           — команда docker, которой вы будете работать;
  containerd.io           — среда выполнения контейнеров;
  docker-buildx-plugin    — сборщик образов (практика 3);
  docker-compose-plugin   — Docker Compose (практика 6).


2.5. Включаем службу:

  sudo systemctl enable --now docker
  systemctl status docker --no-pager

Ожидаемый ответ — строка «Active: active (running)». Выход — q.


=========================================================================
ШАГ 3. ПРОВЕРЯЕМ, ЧТО ВСЁ РАБОТАЕТ
=========================================================================

На машине admin:

  docker version

В выводе две части: Client и Server. Если Server отвечает — Docker
работает. Если вы видите ошибку «Cannot connect to the Docker daemon»,
значит, демон не запущен: разбор в конце практики.

  docker info

Тут много строк, и сейчас не нужно их все понимать. Найдите две:

  * Containers — сколько контейнеров у вас есть;
  * Images — сколько образов.

И главная проверка — запустить контейнер:

  docker run --rm hello-world

Что произойдёт по шагам:

  1. команда docker обратится к демону и попросит образ hello-world;
  2. образа в системе нет, и демон скачает его из интернета;
  3. из образа будет создан контейнер и запущен;
  4. программа напечатает приветствие и завершится;
  5. флаг --rm удалит контейнер после завершения.

В выводе должна быть строка «Hello from Docker!». Поздравляю: Docker
работает, интернет есть, контейнер запустился.

ЧТО ТАКОЕ КОНТЕЙНЕР, ЕСЛИ ОДНОЙ СТРОКОЙ. Это процесс на вашем
компьютере, которому ядро показало другую картину мира: своя файловая
система, свои процессы, своя сеть. Виртуальной машины здесь нет —
и это главное, что нужно понять с самого начала. Подробно разберём
в практике 2.


=========================================================================
ШАГ 4. ЧТОБЫ НЕ ПИСАТЬ SUDO
=========================================================================

Проверьте, в каких группах вы состоите:

  id -nG

Если в списке нет docker:

  sudo usermod -aG docker "$USER"

и после этого ОБЯЗАТЕЛЬНО выйдите из системы и войдите снова.
Группы применяются при входе, поэтому до повторного входа Docker
будет требовать sudo.

ГРУППА docker — ЭТО ПРАВА ROOT, И ЭТО НАДО ЗАПОМНИТЬ

Дело в том, что команда docker разговаривает с демоном через файл
/var/run/docker.sock, а демон работает от root. Кто может записать
в этот файл, тот может попросить демон сделать что угодно.

Проверим, что это не преувеличение. От имени engineer, без sudo:

  docker run --rm -it -v /:/host alpine:3.24 sh

  # внутри контейнера:
  cat /host/etc/shadow
  exit

Вы прочитали файл с паролями всех пользователей машины. Никакого
взлома не было: вы сами попросили демон показать корень системы
внутри контейнера, а демон работает от root и не спрашивает зачем.

ВЫВОД: добавлять пользователя в группу docker можно только тем,
кому вы готовы дать root на этой машине. На сервере, где в группе
docker десять человек, у вас десять администраторов. Как это
ограничивают правильно — практика 12.

  ИСПРАВЛЕНО: в прежней версии курса после установки предлагалось
  выполнить команду создания группы docker. Этого делать не нужно:
  пакет docker-ce создаёт группу сам, а команда завершается ошибкой
  «group already exists» и пугает студентов, которые думают, что
  установка не удалась.


=========================================================================
ШАГ 5. ПЕРВЫЙ КОНТЕЙНЕР, С КОТОРЫМ МОЖНО ПОГОВОРИТЬ
=========================================================================

Запустим контейнер и зайдём внутрь него:

  docker run --rm -it alpine:3.24 sh

Флаг -it означает «оставить ввод открытым и выделить терминал».
Без них оболочка внутри контейнера не получит ввода и сразу
завершится.

Вы оказались внутри. Обратите внимание на приглашение вида / # —
вы root в контейнере. Посмотрим, что здесь есть:

  cat /etc/os-release

Написано Alpine, хотя на машине Ubuntu. Это файловая система образа,
а не вашей машины.

  ps aux

Процессы только свои. Чужих процессов не видно: у контейнера своё
дерево процессов.

  ip addr

Один сетевой интерфейс с адресом вида 172.17.0.x — это адрес
контейнера в сети Docker, а не адрес машины.

Выход:

  exit

Почему внутри минимальный набор программ: образ alpine весит
всего 8 МБ, в нём нет ни curl, ни vim. Это не поломка,
а смысл контейнеров: внутри только то, что нужно приложению.
Подробнее — практика 3.


=========================================================================
ШАГ 6. ГДЕ ЧТО ЛЕЖИТ
=========================================================================

Всё, что скачал и создал Docker, хранится в одном каталоге.
Посмотрите на него:

  sudo du -sh /var/lib/docker
  sudo ls /var/lib/docker

  image/        — скачанные образы;
  containers/   — контейнеры и их журналы;
  volumes/      — данные, которые должны переживать контейнеры;
  overlay2/     — файлы образов на диске.

ЧТО ИЗ ЭТОГО СЛЕДУЕТ ЗАПОМНИТЬ СРАЗУ:

  * удалять файлы внутри /var/lib/docker руками нельзя. Docker ведёт
    свой учёт, и образ после такого удаления перестанет запускаться.
    Чистить нужно командами — это практика 2;

  * если на машине кончилось место, смотреть надо сюда:
      sudo du -sh /var/lib/docker/*

  * данные, которые нужно сохранить, внутри контейнера не хранят:
    контейнер удаляется — данные исчезают вместе с ним. Для этого
    есть тома, и это вся практика 4.


=========================================================================
ШАГ 7. ОБНОВЛЕНИЕ DOCKER
=========================================================================

Docker обновляется как обычный пакет:

  sudo apt update
  apt list --upgradable 2>/dev/null | grep docker

Перед обновлением на рабочей машине помните простое: обновление
перезапускает службу Docker, а вместе с ней останавливаются все
контейнеры на машине. Поэтому обновление делают в окно обслуживания,
а не в разгар рабочего дня.


=========================================================================
ШАГ 8. СДЕЛАЙТЕ СНИМОК ВИРТУАЛЬНЫХ МАШИН
=========================================================================

Сейчас стенд чистый: Docker установлен, ничего лишнего нет. Дальше
будет много экспериментов, вплоть до удаления образов и томов
с данными. Возможность вернуться к исправному состоянию за пару
минут экономит часы.


=========================================================================
ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
=========================================================================

ПРОБЛЕМА: docker: command not found

Пакет не установился. Проверьте по порядку:

  1. репозиторий подключён:
     cat /etc/apt/sources.list.d/docker.list
  2. ключ на месте:
     ls -l /etc/apt/keyrings/docker.asc
  3. apt update проходит без ошибок:
     sudo apt update

Ошибка «NO_PUBKEY» означает, что ключ не скачался или скачался старый.
Актуальный путь ключа — /etc/apt/keyrings/docker.asc.

ПРОБЛЕМА: permission denied while trying to connect to the Docker
daemon socket

Полный текст ошибки:

  permission denied while trying to connect to the Docker daemon socket
  at unix:///var/run/docker.sock: ... connect: permission denied

Причина всегда одна: группа docker у вашего пользователя ещё
не применилась. Проверьте:

  id -nG

Если docker в списке есть, а ошибка осталась — вы не вышли из системы
после добавления. Выйдите и войдите. Быстрая проверка без выхода:

  newgrp docker

ПРОБЛЕМА: Cannot connect to the Docker daemon
at unix:///var/run/docker.sock

Это другое: группа в порядке, а демон не запущен. Смотрите причину
в журнале службы:

  sudo systemctl status docker --no-pager
  sudo journalctl -u docker -n 50 --no-pager

Обычные причины:

  * «Address already in use» — порт занят другой программой;
  * «No space left on device» — кончилось место, проверьте df -h;
  * служба просто не включена: sudo systemctl enable --now docker.

ПРОБЛЕМА: docker run hello-world отвечает таймаутом или ошибкой TLS

  Error response from daemon: Get "https://registry-1.docker.io/v2/":
  net/http: TLS handshake timeout

Значит, демон не может дойти до реестра образов. Проверяйте:

  1. есть ли интернет вообще:
     curl -s -o /dev/null -w '%{http_code}\n' \
         https://registry-1.docker.io/v2/
     Ответ 401 — это нормально: реестр требует входа, но он ответил,
     значит связь есть;
  2. работает ли разрешение имён:
     getent hosts registry-1.docker.io
  3. нет ли в сети прокси. Docker не берёт настройки прокси
     из переменных окружения пользователя;
  4. не блокирует ли файрвол исходящие соединения.

Отдельный случай: таймаут случается сам по себе, без всяких настроек.
Это медленный реестр, а не ваша ошибка. Повторите команду.

ПРОБЛЕМА: контейнер запускается, но не видит сеть

Проверьте, что сеть Docker вообще поднялась:

  docker network ls
  ip addr show docker0

Если интерфейса docker0 нет — разбираться нужно в практике 5.
Скорее всего, дело в правилах файрвола или в настройках сети
виртуальной машины.
